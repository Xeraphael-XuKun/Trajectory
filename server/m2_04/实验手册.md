# M2-4 CLIP 关系结构蒸馏实验手册

本方案不学习 prompt，不运行文本塔。`loss/clip_relation.py` 提供按真实身份与模态聚合 post-BN 中心、排除身份对角后重新 softmax 的九组关系 KL；教师关系应由训练集 RGB 原始 CLIP 中心离线生成，并只在训练 batch 身份子矩阵上取值。少于 3 个身份返回零。

静态/CPU预检：

```bash
cd /mnt/cache/wanghanzhi/XK/Trajectory-m2-d
/mnt/cache/wanghanzhi/envs/llmpar/bin/python3 -m py_compile loss/clip_relation.py
```

正式训练命令（单卡前台）：

```bash
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 /mnt/cache/wanghanzhi/envs/llmpar/bin/python3 train.py --config_file configs/m2_04_clip_relation_distill.yml
```

配置固定 `lambda_rel=0.2`、教师/学生温度 `0.07`、post-BN 中心、60 epoch。主训练已接入一次总损失更新；当前未生成训练集教师缓存，也未完成 GPU/正式训练验证；不得将关系KL下降当作检索成功证据。推理仅保留原 C0。

缓存构建（必须由训练集 RGB 原始 CLIP 特征准备步骤提供已核验的中心和 PID 顺序；不读取 query/gallery）：

```bash
CUDA_VISIBLE_DEVICES=0 /mnt/cache/wanghanzhi/envs/llmpar/bin/python3 tools/build_m2_rgb_centers.py --data-root /mnt/cache/wanghanzhi/Datasets/WHU-MARS --clip /mnt/cache/wanghanzhi/Datasets/ViT-B-16.pt --output /mnt/cache/wanghanzhi/XK/outputs/m2-d/artifacts/rgb_identity_centers.pt
```

该命令从 `train/RGB` 原图运行冻结原始 CLIP，先按身份—相机求均值、再对相机等权聚合，并同时生成关系文件；不是读取 query/gallery 或一次 batch 的临时特征。

```bash
CUDA_VISIBLE_DEVICES=0 /mnt/cache/wanghanzhi/envs/llmpar/bin/python3 tools/build_m2_relation_cache.py --centers /mnt/cache/wanghanzhi/XK/outputs/m2-d/artifacts/rgb_identity_centers.pt --pid-order /mnt/cache/wanghanzhi/XK/outputs/m2-d/artifacts/train_pid_order.pt --output /mnt/cache/wanghanzhi/XK/outputs/m2-d/artifacts/clip_identity_relation.pt
```
缓存必须含 `centers[train_pid,512]`、`relation[train_pid,train_pid]`、`pid_order`，来源为冻结原始 CLIP、训练集 RGB、项目 CLIP normalization 与 256×128 几何；`pid_order` 必须使用数据集训练阶段的 relabel 后整数标签顺序（与 batch 的 `vid` 一致），不是 query/gallery 原始 PID。运行前核对权重标识和 PID 映射；加载时会对每个 batch 身份显式查表，缺失直接报错。
