## 可选的独立预检

需要诊断数值或显存时才运行预检；可以全部跳过，直接执行下一节的正式命令。以下命令每次只运行一条：

```bash
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/preflight.sh W_S_B
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/preflight.sh W_S_T
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/preflight.sh W_C_B
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/preflight.sh W_C_T
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/preflight.sh L_S_B
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/preflight.sh L_S_T
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/preflight.sh L_C_B
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/preflight.sh L_C_T
```

预检使用本组真实配置、解释器、数据及 CLIP 权重。检查训练逻辑 batch=64 / 实际192图像的 AMP forward/backward/一步 Adam、有限 loss/gradient、Trajectory 非零 gain gradient，以及 fp32 测试 batch=1024 的 before/after 768D 特征和峰值显存。

一次性数值预检的 AMP 初始 scale 使用 1024，并写入预检报告，避免默认高 scale 的初期跳步被误判为梯度失效。正式八组训练保持原 `GradScaler()` 默认初始 scale=65536，照实记录 AMP 跳步；预检通过不保证正式训练不跳步。

成功后产生 `logs/preflight_1001/<ID>/preflight_ok.json`，仅作为可选诊断记录，正式启动不读取它。只出现 `PREFLIGHT_OK` 代表预检通过，**正式训练尚未启动**。不保存预检 checkpoint。控制台日志追加写入；重新运行同一诊断目录会更新其中的配置、运行时和报告。

## 八个正式前台启动命令

以下每条命令独立，不能加 `&` 或使用 `nohup`，不能同时运行。建议在可保持连接的交互式会话中，每对先 B 后 T：

```bash
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/run_W_S_B.sh
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/run_W_S_T.sh
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/run_W_C_B.sh
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/run_W_C_T.sh
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/run_L_S_B.sh
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/run_L_S_T.sh
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/run_L_C_B.sh
bash /mnt/cache/wanghanzhi/XK/Trajectory/server/run_L_C_T.sh
```

每份脚本都写明完整的 Python、代码/配置/数据/权重/输出绝对路径和关键参数；不依赖未定义变量。设置 `CUDA_VISIBLE_DEVICES=0`、`WORLD_SIZE=1` 后直接前台执行：

1. `finetune.py`：60 epoch，pre-BN 监测，生成 `transformer_60.pth` 和 `training_summary.json`。
2. `test.py ... TEST.NECK_FEAT before`：完整加载同一 epoch-60 权重，写入 `pre_bn/`。
3. `test.py ... TEST.NECK_FEAT after`：完整加载同一 epoch-60 权重，写入 `post_bn/`。

`set -euo pipefail` 使实际训练或测试失败后停止。每阶段前台管道的 `tee -a` 追加保存控制台输出和错误 traceback 到 `logs/matrix_1001/<ID>.{train,pre,post}_console.txt`；不转入后台。已有输出目录不会阻止启动，运行时按本次配置更新记录。重新运行完整脚本会从 CLIP 初始化重新训练，并在第60 epoch写入同名权重；不会自动断点续训。两个读出都保持本组 normalization 和解释器。

## 单独补做测试

若 60 epoch 已成功，只需补测时，直接使用已有 checkpoint。例如 W_S_T 的 post-BN：

```bash
cd /mnt/cache/wanghanzhi/XK/Trajectory
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 /mnt/cache/wanghanzhi/envs/whu_mars/bin/python3 -u \
  /mnt/cache/wanghanzhi/XK/Trajectory/test.py \
  --config_file /mnt/cache/wanghanzhi/XK/Trajectory/configs/W_S_T.yml \
  TEST.WEIGHT /mnt/cache/wanghanzhi/XK/Trajectory/logs/matrix_1001/W_S_T_seed1234/transformer_60.pth \
  TEST.NECK_FEAT after \
  OUTPUT_DIR /mnt/cache/wanghanzhi/XK/Trajectory/logs/matrix_1001/W_S_T_seed1234/post_bn
```

其余关键参数由完整配置固定；该命令不训练。pre-BN 对应 `before` / `pre_bn`。不要重新运行完整训练脚本来补一次测试。

## 失败、重试与结果汇总

可以直接重新运行本组脚本，无需先检查或重新预检。若希望分开保存每次尝试，可自行使用独立 `_retry1` 输出目录，并同步修改该组配置的 OUTPUT_DIR、启动脚本的训练输出和两个 TEST.WEIGHT/测试输出。修改 batch 或学习率时，应保持 B/T 配对配置一致并记录协议变化。训练开始会把本次 `training_summary.json` 标记为未完成，避免旧完成标记被误用。

只有 `training_summary.json` 标注 `complete=true`、`epochs_completed=60`，且两个独立测试各有 `metrics.json`，才能把该组记为完成。10/20/... epoch 的监测日志不用于选 checkpoint。汇总：

```bash
/mnt/cache/wanghanzhi/envs/whu_mars/bin/python3 /mnt/cache/wanghanzhi/XK/Trajectory/tools/summarize_matrix.py \
  --root /mnt/cache/wanghanzhi/XK/Trajectory/logs/matrix_1001 \
  --output /mnt/cache/wanghanzhi/XK/Trajectory/logs/matrix_1001/八组结果汇总.md
```

汇总保存 Markdown 和 JSON，并列列出性能最优和消融增益最大的候选。缺组时仅显示现有结果和缺失项，八组收齐后再比较两个候选。若使用独立重试目录，汇总前将工具 `collect()` 的该组路径明确改为实际成功的目录，并在报告中注明；不能把不同运行的训练记录和测试记录拼接。
