# M2-1 跨条件多原型文本桥接

本 worktree 从 `a8349abeb5fb62b5f7d233e33202d1ef1d113b42` 派生，分支为 `codex/m2-a`，代码目录为 `/mnt/cache/wanghanzhi/XK/m2-a/Trajectory`。`M2.VARIANT=condition_text_bridge` 单独启用 M2-1；关闭 `M2.ENABLED` 或设置 `M2.VARIANT=none` 时不读缓存、不计算辅助损失，保留原 C0 前向和 CE/Triplet 路径。

主训练使用原始 CLIP 视觉权重、dense C0、PKM、CLIP normalization、seed1234、Adam、60 epoch 和原有增强。`global_feat @ base.clip_proj` 是 768→512 的联合空间投影；`clip_proj` 显式冻结，但输入梯度仍回到视觉特征。全部条件损失使用训练集文本银行的 log-mean-exp 身份原型；跨条件项仅排除当前输入光谱，平台条件仍按实际存在项参与。文本塔和 prompt 阶段在主训练外完成。

## 工件和启动顺序

`build_clip_cache.py` 会遍历 `WHU_MARS.train`，只读取 train 图像并生成 CLIP 特征；随后 `build_train_clip_cache.py` 再校验字段。生成的缓存包含 `feature/features [N,512]`、`pid/pids`、`cams`、`modality/modalities`、`platform`、`pid_map` 和预处理/权重元数据，拒绝 query/gallery。随后依次执行：

```bash
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 bash /mnt/cache/wanghanzhi/XK/m2-a/Trajectory/server/m2/m2_01_preflight.sh
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 bash /mnt/cache/wanghanzhi/XK/m2-a/Trajectory/server/m2/m2_01_prompt.sh
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 bash /mnt/cache/wanghanzhi/XK/m2-a/Trajectory/server/m2/m2_01_train.sh
```

prompt 脚本先生成并校验 train-only cache，再执行 10,000 个实际 prompt optimizer step，生成 `condition_text_bank.pt`。学生脚本以前台方式调用本 worktree 的 `train.py` 和 `m2_01_condition_text_bridge.yml`，输出 `/mnt/cache/wanghanzhi/XK/m2-a/logs/student`。本轮不启动正式训练。

训练完成后，使用同一 epoch60 checkpoint 分别设 `TEST.NECK_FEAT=after` 作为 post-BN 主读出和 `TEST.NECK_FEAT=before` 作为 pre-BN 补充读出；两次评测不得更换 checkpoint。
