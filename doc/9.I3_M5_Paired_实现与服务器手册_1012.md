## 2. 实际方法和配置

主入口是 `tools/iclr_exp/train.py`，该分支默认配置为 `configs/iclr_exp/m5_paired.yml`。配置按 defaults → 原 C0 → common → I3 → resources → 命令行依次合并，并落盘。

`ICLR_EXP.VARIANT=m5_paired`、`PAIR_RNG=replay`、`PROJECTION_TRAINABLE=False`。旧 `M2.ENABLED=False`、`MODEL.TEXT_ALIGN=False`，不启用 TGVA、OneSided、额外文本 hard CE 或 gain-only 更新。

每个主训练 batch 的顺序：

1. 冻结旧条件教师在 eval/no_grad 和原视觉 AMP 下，对同一批已增强图像计算一次原/中性目标。
2. 新学生运行一次完整 C0-on 视觉图，保存 on 前的 CPU/当前 CUDA RNG。
3. 在 `fork_rng` 内重放相同 RNG，运行一次完整 C0-off 视觉图，全部 11 处注入为零。退出时外部 RNG 回到 on 后的状态。
4. 仅 on 特征调用一次原 BNNeck/classifier，计算原 CE/Triplet。off 不 detach，反传共享 backbone。
5. 两项身份 KL 求平均，再统一反向、unscale、全模型裁剪 1.0、一次 Adam 更新。

令 `raw_off=mean_i KL(pT_i || pS_off_i)`，`raw_on=mean_i KL(qT_i || pS_on_i)`：

```text
L_pair = 2² × (raw_off + raw_on) / 2
L_total = L_CE(on) + L_Triplet(on) + 0.5 × L_pair
        = L_CE(on) + L_Triplet(on) + raw_off + raw_on
```

KL 对 500 个身份求和，对全部图像求平均，不按平台均分。语义投影/logits/softmax/KL 保持 FP32。原投影 P0、T0、偏移 d 和教师均冻结。

新学生从原始 CLIP 和全零 dense C0 初始化。首发设置保持：seed1234、60 epoch、256×128、PKM 16 ID×4 图/模态×3=192 图、`IMS_PER_BATCH=64`；backbone LR=5e-6、gain/头 LR=3.5e-4、Adam wd=1e-4；warmup100调度步，起点0.01，cosine下限0.002。原 CE/Triplet、数据增强、sampler 和调度器不改变。没有新增可训练投影或 prompt。

推理只运行 C0-on，输出原 768 维特征；完整/部署 checkpoint 都不注册 teacher/T0/d/off 独立参数。部署评测不读取教师或偏移缓存。

## 4. 前台启动命令

在 I3 分支代码已同步、旧资源存在后，依次执行；预检失败时先处理报告，不启动正式训练。

```bash
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 bash /mnt/cache/wanghanzhi/XK/iclr-i3/Trajectory/server/iclr_i3/prepare_stats.sh
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 bash /mnt/cache/wanghanzhi/XK/iclr-i3/Trajectory/server/iclr_i3/preflight.sh
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 bash /mnt/cache/wanghanzhi/XK/iclr-i3/Trajectory/server/iclr_i3/run_train.sh
```

恢复完成 epoch 边界的完整状态：

```bash
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 bash /mnt/cache/wanghanzhi/XK/iclr-i3/Trajectory/server/iclr_i3/run_train.sh --resume /mnt/cache/wanghanzhi/XK/Trajectory_runs/iclr_I3_M5_Paired_seed1234/resume_latest.pth
```

恢复包括学生、optimizer、scheduler、GradScaler、CPU/CUDA/Python/NumPy RNG、成功更新/AMP跳步计数、资源指纹、固定训练审计面板和固定增强梯度面板。不能恢复到 epoch 内任意 batch。

## 5. 工件与诊断

- `training_terms.jsonl`：raw off/on KL、两项均值、含 Td² 的 KD、外层加权项、CE/Triplet、总 loss、LR、裁剪前全局梯度范数、成功 step、AMP 跳步。
- `run_manifest.json`、`config_merged.yml`、`optimizer_roles.json`、`stage_budget.json`、`epoch_budget.jsonl`：代码提交、资源与缓存指纹、实际 batch/更新、计时和显存；主训练每批一次教师和两次学生，有限额外诊断单独说明。
- `neutral_stats_summary.json`：共享缓存 hash、相机图像数/ID覆盖、d norm/maxabs/类别均值、配对身份差、5折诊断。
- `audit/epoch{0,10,30,60}.json`：固定干净训练面板，raw/neutral/on/off 身份目标质量、四項正确/交叉 KL、学生/教师 JS、中心化 logit 变化方向余弦与范数比、gain/11层实际修正比、特征差、P0漂移。零范数方向记 `null`（NA）。
- `gradient_epoch{1,10,30,60}.json`：身份、加权 off KD、加权 on KD 在 gain、最后 QKV、最终 LN/头上的梯度范数/夹角；不写 `.grad`，不多执行 optimizer。
- 梯度探针复用第一个实际增强 PKM 张量，临时 eval BN/DropPath、原视觉 AMP，并恢复 RNG/模式。因此是固定增强输入诊断，不能冒称主训练随机状态下的原图梯度。额外探针计算含在训练循环计时中，不等于“每批仅三次前向”的完整运行预算。
- `resume_latest.pth`、`transformer_60.pth`、`transformer_60_student.pth`：完整恢复/固定最终完整/部署学生工件。
- `evaluation`：同权重 post 主读出/pre 补充、SYSU原过滤、ALL/9模态/平台/6×6条件分组、FP32归一化特征与路径索引、ALL/G→A/Thermal相关方向逐 query 排名。
- `handoff/I3_实验结果说明.md`、`handoff.json`、配对 CSV：I3 对 C0/M5/I2 的改善/削弱/不变、错→对/对→错、首个正例 rank 迁移和新增错误 top1 条件。未看图时不编造遮挡、颜色等解释。
