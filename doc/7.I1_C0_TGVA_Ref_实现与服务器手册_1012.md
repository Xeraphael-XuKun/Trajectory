## 2. 方法与实际接入

开启分支先执行原 C0，经过原 BNNeck/classifier，得到原身份 CE 和 pre-BN batch-hard soft-margin Triplet。随后完整运行关闭全部11处 C0注入的共享视觉网络；关闭分支不经过 BN/classifier，保留 backbone 梯度。两次视觉前向自然使用独立 DropPath 随机流，不重放掩码、不 detach。

六锚点列序：RGB-G、RGB-A、IR-G、IR-A、Thermal-G、Thermal-A，即 `2*modality+platform`；Ground=0，Aerial=1，零基 camera 5/6 为航拍。

固定模板：

```text
a photo of a [V] view [M] person with [C1] [C2] [C3] [C4] .
```

两枚视角向量以 ground/aerial 词嵌入初始化，三枚模态向量以 rgb/infrared/thermal 初始化，四枚共享 context 使用 Normal(0,0.02²)。可训练 prompt 共4608参数。使用现有、严格加载的 CLIP 文本塔，冻结文本参数、保留输入梯度、保持 causal mask，从实际 EOT读出。每步只编码六条 prompt 一次。

本地配套 tokenizer 实测：六个替换槽位 `[5,7,10,11,12,13]`，EOT位置15，总长度77；词初始化必须为单token，否则报错，不取首个subtoken蒙混。

两支 pre-BN 特征经过同一可训练 `base.clip_proj`，归一化后与六锚点计算 logits。固定 scale 为原始 CLIP `exp(logit_scale)`，不是 `1/0.07`，也不额外引入 KD 温度。

每图辅助量：

```text
a_i = CE(h_off, 2*m+v) + CE(h_on, 2*m)
raw_TGVA = mean(a_i over Ground) + mean(a_i over Aerial)
L = original_CE + original_Triplet + 5*raw_TGVA
```

空平台子集贡献零，不再平均两个平台/分支/模态。均匀六类、双平台时 raw=4log6；单平台时 raw=2log6。投影和语义 loss使用FP32；原视觉训练继续AMP。所有辅助从第一步开启。

`ICLR_EXP.ENABLED=False` 时不构造新prompt，不读取新资源，不增加前向、损失或随机数消耗。新配置明确关闭历史 TEXT_ALIGN/VPR/MOD_DELTA、M2、同步采样和额外损失。源提交不含 C0_AUX/TERMINAL_REPAIR命名空间，因此没有以合并其他分支的方式引入它们。

## 5. 服务器前台命令

代码部署到建议目录后执行。脚本从自身路径定位仓库，因此clone目录名可以更改；命令中的绝对脚本路径须对应实际checkout。I1当前本地实现完成后先提交；GitHub是否已推送须以当前任务回复为准，不能把下列部署接口当成已推送声明。

必要预检（默认核验192张合成图的正式逻辑batch尺寸，另含小型真实训练审计面板；不启动完整训练）：

```bash
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 bash /mnt/cache/wanghanzhi/XK/Trajectory-iclr-i1/server/iclr_i1/preflight.sh
```

必须出现 `I1_PREFLIGHT_OK`；若OOM，不直接减正式batch或改Triplet池。先记录显存与失败位置；需要checkpointing等改动时单独核对随机性和公式。

正式60epoch训练：

```bash
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 bash /mnt/cache/wanghanzhi/XK/Trajectory-iclr-i1/server/iclr_i1/run_train.sh
```

## 6. 产物与分析口径

- `resume_latest.pth`：每epoch末原子替换，保存student+TGVA文本辅助、Adam/scheduler/scaler、Python/NumPy/torch CPU/CUDA RNG、实际计数、完整配置、源码commit/dirty diff、资源manifest、审计面板和初始投影/锚点。
- `transformer_60.pth`：固定最终完整训练工件；`transformer_60_student.pth`：仅原C0视觉学生/BN/classifier及兼容投影，无文本塔、prompt和辅助分支。两个工件对应视觉张量逐元素核对。
- `training_terms.jsonl`：每50实际batch分项CE/Triplet/raw TGVA/加权TGVA/总loss、classifier准确率、所有参数组实际LR、GradScaler、未裁剪梯度范数和裁剪系数。
- `epoch_budget.jsonl` / `stage_budget.json`：实际每epoch/累计batch、成功更新、AMP跳步、训练循环/周期评测/审计时长、显存。wall_seconds采样于checkpoint写入前，包含此前epoch保存开销，最终保存耗时不应凭该字段推算。
- `audit_panel.json` / `audit/epoch0,10,30,60.json`：最多16配对身份和16地面-only身份，每实际模态/相机固定取一图；六锚点、四格任务、log-odds、投影漂移、gain、实际修正比、on/off特征与联合空间差异。
- `gradient_epoch1,10,30,60.json`：预定首个真实训练batch的身份/TGVA分项梯度范数与夹角，不写回 `.grad`，不增加更新。数值零仅是当前精度的观测，不据此断言不存在理论梯度。
- `eval_epoch60`：同一权重的归一化FP32 pre/post特征、完整query/gallery索引、ALL与九模态/四平台/6×6条件/固定全gallery query分组、逐query AP/INP/首正例rank/R@1/5/10/top1负例信息；单独保存G→A逐query。无有效query记null/NA。
- `handoff`：自包含中文测量结果、manifest/预算/机制证据及JSON；有匹配参考时另导出改善/削弱/不变、top1正确↔错误、首正例rank变化和新增负例条件的CSV与案例。

仅同一完整gallery的query分组可以加权还原ALL；受限gallery九格/平台/条件成绩不能平均成ALL。未查看图像时不把错误案例归因于遮挡、背景或模糊。条件分类达标和on/off差距增大都不等于检索改善；I1的结论最多是TGVA目标在本项目中的迁移效果。
