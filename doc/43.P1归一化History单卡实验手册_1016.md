## 2. 先单独执行192图AMP预检

ACP任务申请1张A800-80GB，前台执行：

```bash
bash /mnt/cache/wanghanzhi/XK/Trajectory_history_p1/server/history_p1/sensecore/preflight_P1.sh
```

脚本固定`CUDA_VISIBLE_DEVICES=0`、`WORLD_SIZE=1`。它实际执行：

```bash
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 /mnt/cache/wanghanzhi/envs/llmpar/bin/python3 -u /mnt/cache/wanghanzhi/XK/Trajectory_history_p1/tools/smoke_history_p1.py --pretrained /mnt/cache/wanghanzhi/Datasets/ViT-B-16.pt --data-root /mnt/cache/wanghanzhi/Datasets --batch-size 64 --num-instance 4 --steps 16 --output /mnt/cache/wanghanzhi/XK/Trajectory_runs/history_round2_1016/P1_preflight_seed1234
```

该工具只重复一个真实192图batch进行16次优化尝试，保持MAX_EPOCHS=60、真实采样器iteration尺度和原100步warmup。循环在这个短批次结束后保存`transformer_1.pth`并停止；这个文件不是完整训练1epoch的结果，也不是正式60epoch续训起点。

检查结束应出现`P1_PREFLIGHT_OK`，并在`preflight_result.json`记录实际图数192、K4、尝试次数、AMP跳步/实际更新、严格重载与梯度检查。至少2次实际更新才通过。初期跳步如实保留；不要把输出存在、无NaN或CPU通过等同于此服务器预检成功。

原llmpar存在已知torch/torchvision版本不配套提示，本次没有自动升级环境；以服务器这次真实预检输出判断是否可继续。

## 3. 再独立启动完整60epoch

预检通过后，单独提交一个1张A800任务，前台执行：

```bash
bash /mnt/cache/wanghanzhi/XK/Trajectory_history_p1/server/history_p1/sensecore/run_P1.sh
```

脚本不会自动运行预检，也不会加载预检权重。它从CLIP预训练及指定随机初始化开始，执行完整训练；随后独立加载`transformer_60.pth`，先post-BN、再pre-BN，二者同一权重。

正式训练的等价入口如下，运行工作目录须为P1代码目录：

```bash
cd /mnt/cache/wanghanzhi/XK/Trajectory_history_p1
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 /mnt/cache/wanghanzhi/envs/llmpar/bin/python3 -u /mnt/cache/wanghanzhi/XK/Trajectory_history_p1/train.py --config_file /mnt/cache/wanghanzhi/XK/Trajectory_history_p1/configs/history_P1.yml MODEL.PRETRAIN_PATH /mnt/cache/wanghanzhi/Datasets/ViT-B-16.pt DATASETS.ROOT_DIR /mnt/cache/wanghanzhi/Datasets HISTORY.STOP_AFTER_EPOCH 0 OUTPUT_DIR /mnt/cache/wanghanzhi/XK/Trajectory_runs/history_round2_1016/P1_seed1234
```

上面的等价入口只训练；通常使用`run_P1.sh`，它还记录代码版本、实际配置并执行两种读出。不要对同一个输出目录重复运行两种入口。启动脚本遇到已存在输出目录会退出；需要另一次尝试时，应显式修改为独立retry目录，不覆盖已有产物。

## 4. 必须对应的正式设置

| 项目 | 配置 |
| --- | --- |
| 方法 | HISTORY.ENABLED=True、METHOD=p1；旧C0/VPR/文本关闭 |
| rank/alpha/token/gain | 64 / 0.25 / patch / linear |
| 状态/写入/预测层 | 状态1–12；写入和预测2–12 |
| 方向 | Anchor＋Corrector之后做768维非仿射LN，epsilon1e-5 |

| loss | CE＋SoftMargin Triplet＋1×11层均值SmoothL1 |

| Predictor/方向网络学习率 | 均1e-4 |

| batch/K/模态 | 逻辑64 / K4 / RGB、IR、Thermal，实际192图 |
| 图像/主干 | 256×128、CLIP ViT-B/16、DropPath0.1 |

## 5. 日志与结果回收

预检与正式输出分开。正式目录应包含：

- `source_commit.txt`、`source_status.txt`、`selected_config.yml`及`resolved_config.yml`。
- `console.log`、`train_log_*.txt`、`history_epoch.jsonl`、`history_gradients.jsonl`、`history_optimizer_initial.json`。
- 完成后的`transformer_60.pth`；`eval_postBN`和`eval_preBN`中的测试日志/指标文件。

`history_epoch.jsonl`应标明`method=p1`、`gradient_clipping=task_prediction_separate_1`；首层correction为0，预测层为2–12；诊断记录原方向与LN后方向RMS、真实修正比例、预测/copy误差。梯度JSONL包含任务/预测组各自裁剪前范数；Predictor任务梯度应为0，gain/Anchor/Corrector的预测梯度应为0。没有PG提升或残差变大就判成功的规则。

脚本记录的是实际resolved配置，不用默认YAML值替代命令行覆盖后的值。只有epoch1–60完成、最终权重加载和两种测试日志齐全，才按正式完成记录。主结果固定epoch60 post-BN，不挑中间checkpoint或换主读出。
