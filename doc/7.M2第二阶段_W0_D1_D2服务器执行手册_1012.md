### D2：正式全测试集重评与逐query配对

```bash
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 bash /mnt/cache/wanghanzhi/XK/m2-r2-diagnostics/Trajectory/server/r2/run_d2.sh
CUDA_VISIBLE_DEVICES=0 WORLD_SIZE=1 bash /mnt/cache/wanghanzhi/XK/m2-r2-diagnostics/Trajectory/server/r2/run_summary.sh
```

完整query/gallery应为6405/93609。每个原epoch60权重一次视觉前向缓存pre/post原始768维FP32特征，评测时L2归一化。按原RGB/IR/Thermal独立loader、各自query在前gallery在后的顺序保持batch边界，同时将特征写入统一索引。post-BN为主，pre-BN为同权重补充。沿用原 `iter_euclidean_distance_chunks`、CPU `torch.argsort`、sysu同相机全部剔除，无rerank，无top-k截断。逐query AP/INP/R1与原eval_func交叉核对；R5/R10按完整排序首正例名次统计。

输出ALL、九个模态协议和平台协议，A→A无有效query记NA。ALL及G→A保存top1错→对/对→错、最近正/负例、距离间隔变化；原图文件和索引可定位改善与削弱的具体样本。`top1_condition_summary.csv`是已有ALL/G→A首位条件分层，不是额外受限gallery实验。`query_examples.csv`固定选择每个协议ΔAP最大五个改善和五个退化，仅供浏览，不能代表整体，也不自动指认遮挡等视觉原因。

先核对 `summary/historical_comparison.json`：历史post ALL的C0 mAP/R1/R5/R10为13.52/33.61/50.05/58.19；原M5为15.01/35.30/52.08/60.39。保存新旧值及pp差值；仅正式全量且两位小数一致才标记重现。若不一致，保留结果及环境/并列距离信息，排查后再作主要分析，不强行改数值。

## 4. 输出、续跑和回传

所有结果在 `/mnt/cache/wanghanzhi/XK/m2-r2-diagnostics/results`，与旧m2-c/m2-e/C0目录分离。各任务前台输出并保存 `run.log` 和 `launcher_exit_code.txt`；0为正常退出，-1为仍运行或未正常结束，非零为失败。

特征/logits有逐步完成计数和缓存签名，相同路径、工件、环境、图像顺序及batch才能继续。中断后原命令重跑，可从最近写入进度继续。预分配npy的完整shape不代表所有图像已完成；必须看progress及最终manifest。不复制本地部分缓存到服务器，不把小样本结果当正式结果。变更资源或执行设置时换新输出目录并记录原因，保留旧证据。

最终应有W0/D1/D2完成manifest。主要回传：

- `summary/0.W0_D1_D2执行结果与诊断_1012.md`、`summary/historical_comparison.json`、`run_status.json`。
- W0 manifest、配置差异、M3检查及optimizer组。
- D1 manifest、group_summary、correctness_active_quadrants、augmentation_metrics、per_image_metrics。
- D2 manifest、metrics_reloaded、paired_summary、top1_condition_summary、query_examples、error_cases、per_query/及图像索引。
- 各任务run.log，特别是发生错误时。

大型权重、特征和logits留服务器即可。报告会保留单seed、固定权重和未目视图像的解释边界；本次不据诊断自动追加训练或扫参。
