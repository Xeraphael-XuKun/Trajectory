# Trajectory 第三轮：Token分工与更新来源（2026-10-02）

## 1. 本轮问题与范围

前两轮结果支持保留C0/T1等已有实现，但尚不支持继续增加门控复杂度或全局扫描加速度系数。第二轮R1—R4没有超过第一轮领先组的总体结果；R2的加速度系数最终接近1，R3/R4解除门控权重衰减后也未取得预期收益。本轮转而回答两个具体问题：加速度应作用于哪些token？整个block的变化是否混合了不同性质的更新？

本轮仅新增P1—P4四组。保留原始dense gain、归一化、插入位置、训练目标和优化设置，不同时叠加T2分支或T4门控。仍采用一个项目、独立模块类、独立配置、独立输出目录；每次模型构造只选择一种Trajectory实现。

## 2. 四组方法

记第l个block输入（已含当前Trajectory修正）为x_l，输出为y_l，完整block速度为v_l=y_l−x_l，加速度为a_l=v_l−v_(l−1)。这些都是网络深度方向的特征变化，不是视频帧运动。下一block前的修正仍为G_l⊙LN(d_l)，LN仅沿每个token的通道维计算，G为原始逐层、逐token、逐通道gain。

| 组别 | 配置variant | CLS方向 | patch方向 | ACCEL_MIX | 主要对照 |
|---|---|---|---|---|---|
| P1 | cls_acceleration | v+a | v | 1.0 | C0、历史T0 |
| P2 | patch_acceleration | v | v+a | 1.0 | C0、历史T0 |
| P3 | attention_velocity | 上一block实际Attention残差 | 同左 | 0.0 | C0 |
| P4 | mlp_velocity | 上一block实际MLP残差 | 同左 | 0.0 | C0 |

P1/P2的ACCEL_MIX=1.0只应用于选中的token角色；另一角色固定为0。这不是按token关闭整个Trajectory：两类token始终保留速度修正。第一处修正尚无两步历史，全部使用速度；随后才有加速度。

P3/P4保留完整Attention和MLP骨干运算，只改变传入下一层Trajectory的更新来源。代码从同一次block前向中返回实际加入残差流的更新，包含已有LayerScale与DropPath结果；不重新执行Attention/MLP，不增加随机采样，也不把当前Trajectory修正混入速度。P3/P4不使用加速度，不做双来源融合。

在12层CLIP ViT-B/16、256×128输入下，共129个token（1个CLS+128个patch），在第2—12个block前共修正11次。四组均只有一个可训练gain，新增参数均为11×129×768=1,089,792，与C0/T0相同；gain零初始化。每次图像前向的历史缓存均重新建立，不跨batch保留。

## 3. 固定实验协议

| 设置 | 本轮取值 |
|---|---|
| 环境、输入归一化 | 既有llmpar、CLIP norm |
| cuDNN | benchmark=True、deterministic=True |
| 数据、随机种子 | WHU-MARS，seed=1234 |
| 训练、batch、采样 | 60epoch，batch=64，PKM，NUM_INSTANCE=4 |
| 优化器 | Adam；预训练骨干LR=5e-6，新模块及新头LR=3.5e-4 |
| 权重衰减 | 1e-4，包括全部新gain；无门控特殊分组 |
| 训练目标 | 沿用base损失；TEXT_ALIGN=False，不加入VTC等其他模块 |
| 主结果 | epoch60权重，post-BN，特征归一化，无reranking |
| 补充结果 | 同一epoch60权重，pre-BN |
| 训练中评估 | 每10epoch一次post-BN；不据此改用最佳epoch作为正式结果 |

每组训练结束后独立重新加载磁盘上的`transformer_60.pth`，先测post-BN，再测pre-BN。历史T0继续采用已有结果，不重训；本轮不扩展多seed或环境/norm对照。

主要比较对应读出的mAP与Rank-1，同时报告Rank-5/10。C0-post为13.52/33.61/50.05/58.19，历史T0-post为13.30/33.60/49.88/57.95（均为百分数，顺序mAP/R1/R5/R10）。不把不同读出之间的差值当作模块收益。

## 4. 实现隔离与配置对应

新增实现位于`model/backbones/token_trajectory_structure.py`。原始`token_trajectory.py`、第一轮各模块前向、第二轮各模块前向、旧YAML与旧启动脚本均不改动。共享backbone只增加选择新模块与返回既有残差的分支；旧方法仍走原有速度计算。优化器、训练入口、损失和评测实现不改动。

| 配置 | 运行时类 | 权重中的method_signature |
|---|---|---|
| trajectory_P1.yml | StructuredTokenTrajectory | [10,12,129,768,1,0] |
| trajectory_P2.yml | StructuredTokenTrajectory | [11,12,129,768,1,0] |
| trajectory_P3.yml | StructuredTokenTrajectory | [12,12,129,768,0,0] |
| trajectory_P4.yml | StructuredTokenTrajectory | [13,12,129,768,0,0] |

方法标识是非训练buffer。现有权重加载检查会拒绝用错误组别的配置评估checkpoint；不能用T0/C0的YAML测试P组，也不能交叉使用P组配置。配置验证要求P1/P2系数为1、P3/P4为0，并沿用已有的互斥增强与无效参数检查。新增组不启用R3/R4的门控免衰减规则。

## 5. 本地验证结果与边界

- 全仓测试49项通过：包括新组角色公式、梯度路由、实际残差来源、零初始化一致性、优化器、缓存重置和权重错配拒绝。
- 与改动前`a391b06`比较，缩小模型上的baseline、T0、C0、T1—T5、R1—R4在非零模块参数及随机训练模式下，输出、梯度和随机状态完全一致。单独测试了DropPath和LayerScale开关。
- 使用真实本地CLIP权重构造完整模型，四组配置映射、1,089,792参数、方法标识、11处插入、优化器与post-BN输出检查通过。完整baseline/T0与历史`1e8440f`的参数、初始化随机状态、双读出及训练输出/梯度检查一致。
- 本地RTX3050 Laptop上四组缩小模型各进行4步AMP前反向，数值有限。此项只验证混合精度基本可运行。
- 八个SenseCore/AutoDL脚本通过LF、Bash语法及模拟解释器记录的实际训练→post→pre参数检查。

以上为本地实现验证，不代表已在服务器llmpar执行正式训练，也不能保证不同GPU间逐位一致；尚无P1—P4的性能结果。验证记录保存在本地忽略目录`work/`，训练产物不入库。

## 6. 结果如何指导下一步

P1/P2用于定位加速度的token角色；即使只有P1较好，也应先解释为该训练条件下的结构选择有效，不能仅凭gain大小认定CLS贡献更大。P3/P4用于区分残差更新来源；某一来源较好时，再考虑把这一来源与获益的token分工组合。若均未超过C0/T1，优先保留已有最佳实现，不以模块更多作为继续组合的理由。

独立命令、路径与补测方法见[第三轮单卡启动手册](10.Trajectory第三轮单卡启动手册_1002.md)。
